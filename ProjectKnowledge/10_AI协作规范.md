# 智能体接手与跟进流程

面向企业团队常用的编码智能体。项目规则统一见 [AGENTS.md](../AGENTS.md)；skills 是可选的操作指导，普通 Markdown 也能完整表达工作流程。各客户端的自动发现能力与工具连接需实际确认。

## 接手一次任务

1. 阅读 [00](00_项目总览.md)、[01](01_当前开发状态.md)，理解目标、当前状态、下一步和明确限制。
2. 检查工作区与近期提交，识别用户已有修改；从 [06](06_代码索引.md) 定位实现，按需要读架构/玩法/配置/Bug 条目。
3. 区分用户要调研、设计、诊断还是直接实现；对已授权工作执行到验证和本地提交，不重复询问批准。关键需求不明时提出必要问题，同时推进独立工作。
4. 在安装、新写工具或采用另一种控制方式前，先按 [14](14_工具与技能维护.md) 盘点已有资源。Unity 编辑器操作优先用当前会话已连接且覆盖需求的 MCP；确有缺口再选择已有替代方式，必要时才引入新依赖。
5. 按影响验证，记录结果与未验证范围；按 [12](12_完整Demo迭代.md) 选择已有入口，按 AGENTS.md 同步当前事实并交付。

## 表达需求与练习提示词

长期的理解需求、主动建议、确认边界和持续反馈规则统一见 [AGENTS.md](../AGENTS.md) 的“需求理解与决策”，无需在每条任务提示中重复。

提出具体任务时，可按下面的结构组织；只填写自己已知且重要的信息，不必凑齐字段。实现位置、工具选择等能由项目确定的细节由执行者查阅决定。

```text
目标：希望实现什么，解决什么问题。
参考：沿用哪项现有效果、案例或规则（已知时注明）。
约束：明确不做什么，哪些现有行为必须保留。
验收：我能观察到什么，才算达到预期。
交付：希望得到什么文件、功能或验证结果。
决策边界：哪些可自主处理，哪些先给方案或样例让我确认。
```

例如：为主角制作 Walk，沿用已认可 Idle 的形象和像素质感，主角不展示武器；要求左右脚换重自然、披风跟随、循环顺畅，交付一张透明等格 PNG 精灵表及切片参数，先确认主角风格后再制作敌人，暂不改正式 Animator。脚底接地标准应结合移动速度与游戏视角验证，不能只凭静态图宣称无滑步。

练习时先用自己的话写目标和验收；希望获得提示词反馈时，可要求指出会影响结果的歧义并给出最小修改版。日常开发不默认变成提示词教学，也不要求用户先掌握技术细节。

## 新聊天与其他模型接手

项目规则、知识库和 `.agents/skills` 中的普通文件是共享入口，不需要安装本项目到某个模型专属目录。客户端未自动读取规则时，用户可直接要求：“先读取 `E:/UnityProject/HeroArena/AGENTS.md`，按项目入口核对当前状态与已有资源，再继续本次任务。”

接手智能体按下表直接读取相关 SKILL.md，并复用其中引用的项目脚本、认可案例和来源记录。个人技能副本仅为便利，不取代仓库源；不要因为技能未显示在列表里就重新下载或重建同类流程。模型/客户端可用的 MCP、工具权限与连接状态须现场核实，历史安装记录不证明当前可调用。具体资源核查与替代条件统一见 [14](14_工具与技能维护.md)。

## skills 路由

本地入口位于 `.agents/skills/<名称>/SKILL.md`。宿主未自动发现时，可直接读取对应文件；未安装的全局 skill 不是项目先决条件。

| 任务 | 按需读取 |
|---|---|
| 接手/健康检查/文档与工程核对 | unity-project-audit |
| 新玩法或系统设计 | unity-feature-design |
| 核心逻辑的行为测试、测试驱动开发与回归修复 | unity-tdd |
| 异常诊断与最小修复 | unity-bug-diagnosis |
| 伤害、状态、导航等跨系统改动审查 | heroarena-change-review |
| Canvas/TMP/按钮/布局 | ui-ugui |
| 实际通过 MCP 操作编辑器 | unity-mcp-orchestrator |
| 分支、提交范围与交付 | unity-git-delivery |
| 文档更新、整理与接续 | heroarena-knowledge-sync |
| 寻找和评估工具、插件、skill、素材处理能力 | heroarena-resource-discovery |
| 角色/特效动作设计、AI精灵表连续性审查与动画交付 | game-2d-animation-designer |

角色/特效动画任务先查看 [15 动画生成知识库](15_动画生成知识库.md) 的同类已认可案例，按需读取权威图集、参考轨迹和提示词；宿主未自动加载skill时可直接读取项目文件。案例参数与认可范围不外推到其他动作。

不要求每次加载全部 skills。同一事实只在对应文档维护，其他地方链接到它。

## 持续维护

用户已授权智能体按项目需要增减和优化仓库内规则、文档及 skills。维护须解决实际重复、过时或缺口，保留有价值的证据和来源，单独提交；不将这份授权扩展为任意购买、账号授权、对外发布或系统设置变更。

被打断时留下当前成果、下一步、未验证项和必要证据位置；下一个智能体先核对这些信息，避免重复执行 Setup、构建或迁移。
