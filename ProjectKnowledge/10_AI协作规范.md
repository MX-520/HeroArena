# 智能体接手与跟进流程

面向企业团队常用的编码智能体。项目规则统一见 [AGENTS.md](../AGENTS.md)；skills 是可选的操作指导，普通 Markdown 也能完整表达工作流程。各客户端的自动发现能力与工具连接需实际确认。

## 接手一次任务

1. 阅读 [00](00_项目总览.md)、[01](01_当前开发状态.md)，理解目标、当前状态、下一步和明确限制。
2. 检查工作区与近期提交，识别用户已有修改；从 [06](06_代码索引.md) 定位实现，按需要读架构/玩法/配置/Bug 条目。
3. 区分用户要调研、设计、诊断还是直接实现；对已授权工作执行到验证和本地提交，不重复询问批准。关键需求不明时提出必要问题，同时推进独立工作。
4. 缺工具时按 [14](14_工具与技能维护.md) 调研；已有能力足够则直接复用。
5. 按影响验证，记录结果与未验证范围；按 [12](12_完整Demo迭代.md) 选择已有入口，按 AGENTS.md 同步当前事实并交付。

## skills 路由

本地入口位于 `.agents/skills/<名称>/SKILL.md`。宿主未自动发现时，可直接读取对应文件；未安装的全局 skill 不是项目先决条件。

| 任务 | 按需读取 |
|---|---|
| 接手/健康检查/文档与工程核对 | unity-project-audit |
| 新玩法或系统设计 | unity-feature-design |
| 异常诊断与最小修复 | unity-bug-diagnosis |
| 伤害、状态、导航等跨系统改动审查 | heroarena-change-review |
| Canvas/TMP/按钮/布局 | ui-ugui |
| 实际通过 MCP 操作编辑器 | unity-mcp-orchestrator |
| 分支、提交范围与交付 | unity-git-delivery |
| 文档更新、整理与接续 | heroarena-knowledge-sync |
| 寻找和评估工具、插件、skill、素材处理能力 | heroarena-resource-discovery |

不要求每次加载全部 skills。同一事实只在对应文档维护，其他地方链接到它。

## 持续维护

用户已授权智能体按项目需要增减和优化仓库内规则、文档及 skills。维护须解决实际重复、过时或缺口，保留有价值的证据和来源，单独提交；不将这份授权扩展为任意购买、账号授权、对外发布或系统设置变更。

被打断时留下当前成果、下一步、未验证项和必要证据位置；下一个智能体先核对这些信息，避免重复执行 Setup、构建或迁移。
