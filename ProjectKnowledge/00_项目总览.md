制作一个用于 Unity/C# 游戏客户端求职展示的独立游戏 Demo。

重点展示：

- Unity 游戏开发能力
- C# 编程能力

- 战斗系统设计能力
- Git 项目管理能力


## 开发者背景

2027 届本科生。

目标方向：

Unity/C# 游戏客户端开发。

希望通过项目深入理解游戏开发，而不是只依赖代码生成。

## 开发原则

1. 优先使用 Unity 已有组件解决问题。

2. 避免为了简单功能增加大量代码。

3. 修改代码前先分析已有架构。

4. 一次推进一个功能。

5. 每完成一个稳定模块进行 Git 提交。

6. 保持项目结构清晰。


## Git管理

使用：

GitHub Desktop

原则：

每个重要功能完成后提交一次。

提交内容包括：

- 中文 Summary
- 中文 Description


## AI协作方式

AI作为：

- Unity开发导师
- 代码分析助手
- Bug排查助手

要求：

- 解释实现原因
- 帮助理解代码
- 不盲目生成代码
- 不破坏已有功能

## AI协作中的资料库维护

AI除了辅助开发外，需要协助维护项目资料库。

当完成重要功能、架构调整或解决关键Bug后，AI应提醒更新对应文档。

需要检查：

- 当前开发状态
- 开发日志
- Bug记录
- 技术架构
- 功能设计

更新原则：

1. 新增功能后，更新当前开发状态和开发日志。

2. 解决重要Bug后，记录问题现象、原因和解决方案。

3. 修改项目架构后，更新技术架构文档。

4. 修改未来开发计划后，更新功能设计文档。

5. Git提交后，可同步记录重要版本变化。

AI不应只解决当前问题，也应提醒保持项目资料与实际代码状态一致。

## 阶段性整理提醒

当一个开发阶段结束时（例如：

- 完成一个系统
- 完成一次较大重构
- Git完成重要提交

AI应主动提醒：

1. 是否需要更新资料库。

2. 是否需要补充开发日志。

3. 是否需要记录新的Bug和解决方案。

4. 是否需要整理面试复盘内容。

避免项目文档长期落后于实际开发状态。
