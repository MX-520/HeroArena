### 动作和特效如何配合

本例为十张原画，每张100ms，总长1秒，非循环。第5帧从0.4秒开始主斩击；这是本例与既有事件时刻对齐的设计，不是通用近战参数。

| 帧 | 身体 / 剑运动 | 特效 |
|---|---|---|
| 01 | 竖剑警戒，支撑稳定 | 无 |
| 02 | 重心后加载，剑向后上引 | 无 |
| 03 | 胸肩后转，剑刃向身后 | 无 |
| 04 | 最大蓄力，保持后引轮廓 | 无 |
| 05 | 从后向前过顶斩出，主斩击开始 | 银白过顶弧，浅蓝灰边缘，跟随剑路 |
| 06 | 向前下方随动，承接重量 | 斩击弧前移；剑前方接触位置短暂黄白闪光 |
| 07 | 前伸后吸收惯性 | 大弧消失，少量金白碎光 |
| 08 | 屈肘回收 | 极少余光衰减 |
| 09 | 收剑回警戒 | 无大特效 |
| 10 | 竖剑归位 | 无 |

### 本次真正有效的经验

1. **角色参考与运动参考分开指定用途。** 先锁定当前角色/武器，再用已有动画研究剑尖路径；避免生成器把参考人物也换进来。
2. **先有可解释的剑路，再用刀光强化它。** 刀光随挥出展开，在接触位置强调力量，然后快速衰减；不在蓄力/待机时常驻发光圆环。
3. **无特效审查只用于诊断。** 能看清身体和握点，不代表完整表现一定更好。最终要用带特效的实际播放效果判断力度；本次用户明确偏好完整刀光版。
4. **允许为清楚的动作结构重绘序列。** 本例从八姿势无特效稿改成十姿势，不能靠给原来的每一帧统一贴一条弧线解决。
5. **生成原板不等于可切割图集。** 原板间距不规则，刀光和断开的火花要一并归属到对应帧，不能只取最大身体连通块而丢掉碎光。整理为等格、透明、固定锚点的图集后再交付。
6. **保留迭代依据。** 剑加长前后的外观、轨迹参考、有效提示词、最终图集和用户反馈需要能追溯；不把未获认可的中间稿悄悄升为定稿。

### 交付参数与验收边界

本例最终PNG为6400×512，横向10格，每格640×512，根锚点为格内左上角坐标[288,448]。Unity若保持原像素导入，使用Multiple，最大纹理尺寸至少8192，Point/无压缩，按640×512网格切片。不要为适应默认纹理上限擅自缩小已认可图。

- **已认可**：用户对完整带刀光版的视觉效果明确认可；单张PNG交付形式已确认。
- **技术已验证**：每个人工区域alpha>80像素完整提取、所属RGBA保留；新旧18张内嵌PNG逐像素一致；播放/逐帧/慢放/循环/停留和控制功能通过。
- **未验证/尚存限制**：未替换正式Unity动画或验证伤害事件、攻击范围、游戏手感；第9帧持械透视、武器/身体轻微漂移待复核。特效当前合成在PNG里，不是独立FX层。

后续 agent 不要仅因“用户喜欢画面”就写成“正式角色替换完成”或“整局回归通过”。内部可以继续检查，默认交付物仍按14中的当前偏好提供，不自动再制作对照页或ZIP。

## 同类任务的执行入口

可以直接接收这样的请求：

> 读取AGENTS.md和ProjectKnowledge，使用game-2d-animation-designer，参考ANIM-001已认可斩击案例，为这个角色制作同类单斩；保持角色身份和刚性武器，按当前偏好交付单张透明PNG。

执行时读取该角色实际规格、原Clip时长/事件及用户最新要求，确定本次关键姿势和特效时机，先完成一个动作。仅当任务确实涉及游戏接入时修改Clip/场景，不把案例复用扩大成自动覆盖正式资产。

## 后续如何增加案例

用户认可了新的动作类型后，在索引增加编号和素材入口，记录：适用范围、权威图集、实际时序/锚点、参考用途、有效提示词、关键迭代原因、认可层级与未验证项。生成完成但未经认可的作品仍放候选目录，不能直接列为已认可案例。数量增长后再把详细案例拆成独立文档，本页保留入口。
