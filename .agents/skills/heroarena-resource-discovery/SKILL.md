# 项目资源选型

复用 [项目工具选型流程](../../../ProjectKnowledge/14_工具与技能维护.md)，先明确能力缺口、交付格式、质量、Unity/平台兼容、商用要求和成本。

- 先盘点当前宿主工具/MCP、本地程序、项目依赖、编辑器/验证脚本、已有 skills 与认可素材，再搜索缺失能力。切换聊天/模型时先直接读取项目路由，不因自动发现列表缺项就重复安装。
- Unity 编辑器操作优先走当前可用且覆盖需求的 MCP；先确认工具暴露与目标工程连接。只有明确不可用、能力不足或有具体可靠性/效率理由才采用其他方式，先复用已有替代入口，记录原因后才考虑新增。普通文件编辑无需强制使用 MCP。
- 使用宿主可用的 Web/GitHub/插件目录，优先官方仓库、文档、许可证、发布记录和实际样例。输出可直接访问的来源链接与核查日期。
- 区分工具许可、模型许可、输入素材权利与输出使用条件；不因工具开源就宣称生成资产可商用。
- 比较维护质量、自动化接口、版本/硬件/账号依赖与成本；star 数或 README 演示不足以证明可靠。
- 先试最小独立样例，再决定接入；记录版本、结果与清理方式。新依赖进入项目时保留来源和必要许可。
- 结果明确标记找到/推荐/安装/验证四种状态；没有连接或搜索能力时说明缺口，不编造可用工具。

已有项目授权内可自主调研、调整本地流程和维护 skills；不自行购买、获取账号权限或更改系统范围设置。只读选型任务不自动变成安装任务。

缺少可复用流程才新增 skill；优先精简/改进已有项，长期操作知识放 skill，项目事实放知识库。
