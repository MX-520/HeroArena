# 知识库同步与精简

项目入口在 `ProjectKnowledge/00_项目总览.md`，分工和接续流程在 `10_AI协作规范.md`。先核对任务差异、实际资产和验证证据。

- 当前事实写入对应当前文档；过程与决策写 03，Bug 证据写 04。只更新发生变化的条目。
- 被替代的现值和阶段计划移到 archive，当前页保留结论与入口；不在多份文档复制整个迭代过程。
- 计划、已实现、已验证分开；用户反馈、本次观察和历史日志分开。日志缺失或未重跑时明确说明。
- Git 历史已保存的普通提交无需逐条抄入 08；资产许可和来源以 13 及资源清单为依据。
- 检查链接、代码路径、命名、参数和前后矛盾。脚本索引覆盖实际文件，不能仅按文档推定实现。
- 用户已授权持续优化本仓库文档与 skills；纯调研/只读任务仍保持请求范围，常规交付所需同步直接执行。

可用 [validate_knowledge.py](scripts/validate_knowledge.py) 检查本地链接、归档哈希、skill 结构与运行时代码索引。它验证资料结构，不证明游戏运行正确；旧归档内容不按现行规则执行。

交付说明维护范围、主要事实变化、结构检查和未验证范围；按 Git 约定保存。
