# Unity 测试选择

## 先看程序集再创建测试

核对 Packages/manifest.json、packages-lock.json、现有测试目录和 .asmdef/.asmref，找到被测脚本实际所属程序集。优先沿用项目已验证的测试入口。

自定义 asmdef 程序集不能引用预定义 Assembly-CSharp。不要生成 references 包含 Assembly-CSharp 的测试 asmdef，也不要仅为写一个测试把所有运行时代码搬进新程序集：这可能改变编译顺序、Editor 引用及序列化类型。若代码仍在预定义程序集，先核实当前 Test Framework 支持的 Editor 目录测试方式；若必须改程序集边界，明确影响，按当前授权处理并检查序列化引用。

NUnit 测试依赖应留在测试/Editor 范围内，不能泄漏到游戏运行程序集。实际发现并执行测试，不能以创建文件或编译成功代替测试发现。新增 Assets 下文件需按项目流程检查 .meta。

## 模式与断言

| 目标 | 优先方式 | 验收重点 |
|---|---|---|
| 数值规则、冷却边界、状态计算、序列化往返 | EditMode，通常 NUnit Test/TestCase | 明确输入和独立预期值；隔离真实存档 |
| Awake/OnEnable/Start/Update、禁用与重生、多帧行为 | PlayMode，按需 UnityTest | 对象激活顺序、状态变化和退出清理 |
| 碰撞、触发器、动画事件联动 | 匹配需求的 PlayMode/既有场景验证 | 固定步进、实际资源与事件配置 |
| 披风自然度、动作力度、像素风适配 | 视觉预览与游戏内审查 | 不以逻辑测试替代视觉验收 |

用 NUnit Test，除非确实需要跨帧等待或特殊 yield 指令再用 UnityTest。MonoBehaviour 通过 GameObject.AddComponent 创建。需要 Start 等生命周期时等待到对应阶段；必要依赖先准备好，再激活对象。不要以编辑模式中的普通方法调用冒充真实生命周期。

尽量控制时间/随机性等外部边界，减少真实秒数等待；已有时钟接口可用时复用。等待异步行为需合理超时，使用浮点容差或区间，避免机器帧率导致偶发失败。只为当前行为引入必要的替身，不模拟整套 Unity 或所有内部组件。

## 隔离与清理

清理测试创建的 GameObject、场景、事件订阅、静态状态及修改过的 Time.timeScale/随机状态等。EditMode 中对测试对象使用合适的即时清理；PlayMode 中销毁后按需要等待帧结束。文件测试写独立临时目录，不覆盖玩家真实存档、PlayerPrefs 或正式 Scene/Prefab。

## 执行与报告

优先复用已工作的 Test Runner/MCP/项目验证入口，并核查实际可用工具。编辑器已打开同一工程时，不盲目再启动一个 Unity 争用项目锁；不关闭用户编辑器。需要独立会话时按项目约定选择隔离副本或既有验证路径。

采用命令行执行时，按已安装 Test Framework 的官方文档核对参数，明确 projectPath、测试模式、过滤范围、日志与结果 XML。用结果文件中的实际测试数量、失败和错误判断结果，同时核对退出码与日志；文件缺失、过期或零测试均不能报通过。不因验证默认启动 Player 构建或打包。

测试覆盖逻辑不能证明 Prefab 引用、动画事件、导航或整局体验已通过；受这些配置影响时补相关场景验证，并记录无法执行的部分。
