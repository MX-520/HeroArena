# 播放与交付

## 清单格式

`python scripts/build_review.py manifest.json --out review`

该示例以skill目录为工作目录。实际任务建议使用脚本、清单和输出目录的绝对路径，将输出写到当前任务目录，避免写进个人skill目录。

相对file以清单所在目录为基准；不指定rect则使用全图。rect为源图左上角坐标；anchor为裁切帧内的像素根位置，并非Unity归一化pivot。没有anchor时默认底部中心并报告假设。

```json
{
  "title": "Walk candidate — review pending",
  "note": "原地朝右，当前为候选。",
  "loop": true,
  "frames": [
    {"file": "walk.png", "rect": [0, 0, 128, 128], "anchor": [64, 116], "duration_ms": 100, "label": "left contact"},
    {"file": "walk.png", "rect": [128, 0, 128, 128], "anchor": [64, 116], "duration_ms": 80, "label": "down"}
  ]
}
```

生成review.html（内嵌帧，无外网请求）、contact-sheet.png、technical-report.json。duration_ms为原画曝光时长。重复帧可能是hold，触边可能是有意拖影，只给提示。工具不判断滑步、穿模或解剖，不自动签署动作验收。

## 审查

正常速度至少看两周期，再慢放/逐帧定位。单次动作看进入与结束，死亡停留末帧。洋葱皮看轨迹和结构漂移，剪影看可读性，彩色看表情、握点、遮挡。倍率仅作审查，不改计划时长。

问题写明：动作、帧/时间、看到什么、影响和修复。静态疑点与已播放观察分开记录。例如“疑似支撑重复，未播放”和“03→04支撑脚突跳，髋未换重”证据不同。

- 形体：头胸髋体积、关节、服装、刚性装备一致，允许有意变形。
- 接地：支撑、腾空和重心能解释运动，结合游戏移速检查滑步。
- 轨迹：握点不脱手、刀尖弧连续，换手和透视有依据。
- 节奏：预备/发力/命中/随动/恢复清楚，特效不遮盖错误。
- 交接：末→首连续，非循环终态不闪回，打断后能交给状态机。
- 技术：真实alpha、尺寸/锚点/帧序一致，无文字、棋盘格或邻帧污染。

结论写“可进入下一阶段 / 需修正 / 证据不足”，注明阶段。自动技术报告与视觉审查分开，不用单个总分替代理由。

## Unity接入

检查GUID/local file ID与meta配对，实际尺寸下核对PPU/采样/压缩，明确pivot和根锚点转换。不要逐帧追包围框中心来掩盖步态问题。

读取既有Clip时长、倍率、循环、事件和转换；按实际命中姿势映射DetectHit/OnAttackFinished等接口，不照抄第几帧。改变时长/窗口须说明玩法影响并验证。

武器与特效独立时核查插槽、镜像、遮挡、巨大化、死亡掉落和打断生命周期，不悄悄改攻击半径/伤害逻辑。按项目要求验证，未经请求不构建。

交付源文件、透明序列或图集、帧时长/锚点、事件映射、来源加工记录、播放证据与剩余问题。缺完整游戏环境时明确未验证范围。
