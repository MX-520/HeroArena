# Unity MCP 操作

Unity 编辑器操作优先复用现有 MCP。先通过当前宿主的工具发现机制确认 Unity MCP 是否暴露，以及目标工程是否连接；工程里安装包不等于当前可调用。宿主不自动加载 skills 时可直接读取本文件。

已连接且覆盖需求时直接使用，不默认新写控制桥接或改用桌面点击。未暴露/未连接、能力缺失或有具体可靠性/效率理由时，说明原因并优先复用项目既有脚本/验证入口；新依赖按项目14评估。普通源码和文档编辑仍可用文件工具。

1. 查询实例、工程、场景与编辑器状态，确认目标及编译/导入是否完成。
2. 按当前工具 schema 和只读资源定位对象/组件，再实施已授权操作；不要将参考里的工具名、URI 或参数当成固定 API。
3. 独立查询可批量执行；对象创建、组件配置、引用绑定等有依赖的修改按顺序执行。
4. 脚本更改后等待编译并读错误；写入工具已触发导入时不重复刷新。画面变更查看实际截图，交互和玩法验证真实运行结果。
5. 断线/忙碌时检查 domain reload、实例和工具组；有限重试后使用已核实存在且适合任务的替代入口，或报告缺口。不假定编辑器桥接必然存在，不把缺工具当作已完成操作。

不要为调用某个 API 随意升级包。不得隐式关闭/保存用户编辑器或运行旧 Setup；现有批处理验证会退出 Unity，先读项目 12 文档。
