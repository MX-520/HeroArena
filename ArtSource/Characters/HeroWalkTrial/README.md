当前候选为[v2双脚交替修订](v2/README.md)。下述首版已被用户反馈“换脚太快，循环像一只脚在走”否定，仅作历史追溯。

## 图集规格

`Hero-Walk-strip8.png` 为 5120×640 RGBA、从左至右8帧，单格640×640，建议10fps、0.8秒循环。格内左上角根锚点[320,544]，Unity归一化pivot[0.5,0.15]。Multiple / Grid by Cell Size 640×640，Max Size 8192，Point，无压缩，关闭Mip Maps。未创建Unity导入meta或修改Animator/Clip。PPU与体高仍需按实际场景校准，不直接套用Idle的PPU。

## 依据与动作意图

已读取项目AGENTS、00/01/10/14/15和动画skill，核对当前工作区与PlayerMovement/EnemyController。当前分支feature/combat-feedback，既有大量用户删除、场景、导航及导入设置改动均保留。

游戏为平面自由移动，x方向控制flipX，Walk使用Speed驱动，主角源码默认步速5、跑速8。当前正式Walk为12fps/约0.667秒，测试Walk为8fps/1秒。本候选为独立动作风格提案，没有覆盖既有时序。无Unity MCP暴露于本会话；本轮仅只读核对代码和资产，不操作编辑器。

身份/画风取ANIM-003的Idle_01；同一白发红眼、空手、皮甲红披风主角，朝右三分之四视角。动作草案设计为接触→下沉→经过→抬升→反侧接触→下沉→经过→抬升；支撑脚相对根向后移动，摆动脚抬起向前，手臂反摆，头腰双起伏，披风中段和末端延迟。草案不是最终角色动画证据。

整板早期候选重复同一领步腿且缺少经过姿势，未采用。随后单独绘制反侧接触关键姿势，再作为最终整板约束输入。图像绘制使用内置image_gen；Python仅按人工确认区域无损裁切、平移、排列，未程序摆动贴图或模糊插帧。所有格采用同一行的共同根坐标，不按每帧鞋底或包围框重新居中。alpha范围0–255，保留低alpha边缘，不把RGBA存储等同于严格低分辨率像素格。

## 验证与限制

- 提取检查：8帧所属区域全部alpha>0像素保留，RGBA逐像素一致，等格、透明留边，见extraction-report.json。
- 播放功能：内部审查器8帧索引、洋葱皮/剪影开关、正常速度2400ms约3轮循环与首尾回绕无脚本错误，见playback-check.json。这是播放器功能检查，不是自动动作美术验收。
- 静态审查：头身、服装、空手和披风身份延续；03/07近远腿遮挡与换重仍是重点，生成姿势不能由文字任务卡视为精确执行。未宣称无滑步、无循环跳变或用户认可。
- 未进行Unity导入、正式绑定、事件、碰撞、排序或游戏内移速匹配检查；未构建。首尾和支撑关系需用户实际观看候选，若未通过应修正关键姿势，不以加帧或加速掩盖。
